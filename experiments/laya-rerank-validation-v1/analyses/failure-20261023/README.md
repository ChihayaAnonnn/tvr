# R@1 下降的原因核查

2026-10-23；这是已完成实验的只读事后分析与真实权重CPU诊断。没有启动GPU、重跑完整精度、训练、搜索参数、改变固定规则或访问test。原study保持关闭，原始产物与报告未修改。

**结论：当前证据支持“这组Laya权重＋四帧证据＋固定二选一模板，不能胜任UATVR Top-10硬负例的直接排序”；没有发现接入错位、选项反转或缓存错误足以解释37.14个百分点下降。原生API复现相同失败。不能进一步把全部损失都归给Laya的一般能力，也未因果分离四帧信息限制、模型细粒度理解、模板及跨视频置信度偏好各自贡献。**

## 1. 下降如何发生

以下均为本地认证MSRVTT validation、10,000查询/500视频、T2V、FP32、DSL=false，原始seed713/epoch05。

| 统计 | UATVR | Laya直接重排 |
|---|---:|---:|
| 全量R@1 | 53.19% | 16.05% |
| GT已进入Top-10的8,683条中，排第一的比例 | 61.26% | 18.48% |
| 上述查询内，GT胜过一个非标注目标候选的平均比例 | 87.49% | 60.61% |
| GT与候选的证据 | 原12帧检索表示 | 4张原始RGB帧 |

在Top-10内均匀随机排列的理论条件命中率为10%，折合全量R@1期望8.683%，不是实际运行的新对照。Laya优于这个随机期望，但显著弱于原始检索器。

基线正确5,319条；重排保留1,087条（20.44%），破坏4,232条，救回518条。因此 `5319 − 4232 + 518 = 1605`，净损失3,714条，即−37.14个百分点。10,000条中8,338条更换第一候选。由于固定规则完全按Laya概率重排Top-10，原先很有用的UATVR候选顺序在大部分查询中被抛弃；这里没有融合或选择性调用来保留它。

GT与同查询非标注目标候选的P(match)分布高度重叠：GT中位数0.3894，同查询负候选中位数0.3105。条件pairwise胜率只有60.61%，不足以稳定从另外9个检索硬负例中选出标注视频。此处“负候选”指非标注目标，不保证视觉语义完全不相关。

## 2. 接入核查：真实权重与真实视频

不只复查单元测试：从原查询顺序中确定性选取“基线正确、Laya错误”的前4个不同GT视频，检查GT与Laya赢家，共4查询/8真实视频对。它们是事后示例，不是随机样本，不能估计错误类别占比。

| 检查 | 观察 |
|---|---|
| 原生predict vs适配器，使用同CPU重新编码的视觉特征 | 两组真实视频对logits最大差0 |
| 直接pixel_values前向 vs同CPU视觉缓存前向 | 同两组logits最大差0 |
| 同查询8个不同候选，batch8 vs逐个batch1 | logits最大差9.5367431640625e−7；小于1e−5 |
| 改变候选请求顺序，再映射回原顺序 | logits最大差0 |
| 4查询/8视频对，原生API输入原始RGB四帧 | 原生API在4个查询中均更偏好原来的错误赢家 |
| CPU使用原GPU缓存 vs已归档GPU批次 | 首批8候选logits最大差3.814697265625e−5，属于跨设备复算，不能与同设备缓存断言混为一谈 |
| CPU重新编码原始帧 vs归档GPU概率 | 8视频对P(match)最大差6.5443965715505925e−6，4组GT/赢家顺序均保持 |

同设备两组为video1011和video7644；异构8候选批次来自query0的原Top-8。其余4查询/8视频对详情见CSV，不应把同设备两组检查写成全validation原生/缓存等价。

实测每视频4×64×576视觉特征、256个图像token；选定输入总长352–372，远小于1024上限，没有截断。帧索引来自原有效12帧的固定均匀子集；输入为解码后的原始RGB，非UATVR224像素反归一化结果。全库500视频均有4个不同有效帧，无padding复制。

原生API按固定identity选项排列生成`match`/`not_supported`，与适配器列0/列1一致。全量P(match)可由归档logits及checkpoint温度精确重算。把方向反过来仅作数组级接线诊断，全量命中反而为4.72%；不是新的候选方法或选点依据。没有精确最高分并列，最低winner/runner-up概率差约5.22e−5，不是四位小数舍入导致的随机乱序。

上游配置会提示顶层pad_token_id=128002，但实际执行的tokenizer pad=2、embedding词表49,280，选定输入最大token ID49,279，均在有效范围；这条警告不能直接归因为本次下降。原生接口对比也不能证明整个上游运行栈无任何问题，只能核查已执行的具体通路。

此前发现的UATVR单查询池化掩码别名问题影响的是性能预热。科学精度入口消费已验证的原始归档分数矩阵，不调用这条新单查询打分路径；该问题不能解释本次Laya重排的精度下降。

## 3. 哪些证据支持模型/任务适配不足

### 3.1 细节已在帧中出现，原生模型仍选错

| 查询摘要 | GT P(match) | 错误赢家 P(match) | 帧证据观察 |
|---|---:|---:|---|
| 开车画面从黑白变彩色 | 0.8013 | 0.8956 | GT四帧含黑白/彩色转换；赢家为汽车展示，未体现该转换 |
| 在油锅煎肉饼后盖锅盖 | 0.3061 | 0.7211 | GT四帧清楚显示煎锅及盖盖；赢家主要为餐厅烤盘大汉堡场景 |
| 巨大的演唱会 | 0.5065 | 0.6793 | GT显示大型观众场；赢家为乐队/键盘演出特写，粗主题相近 |

[四组GT与赢家的实际输入帧](case-figure.jpg)。原生API的概率四舍五入到四位，表中仅用于展示；正式排序使用未舍入的归档概率。

这排除了“所有失败都只是没采到关键证据”的解释。示例支持细粒度属性/时序和场景区分不足，但不代表已量化全部失败原因。另一些查询涉及声音、身份、短暂动作或先后关系，四帧确实可能证据不足；本次没有通过改帧数的科学对照量化这部分。

### 3.2 个别候选被跨查询过度偏好

| 视频 | 进入原Top-10次数 | Laya选第一次数 | 其中命中标注次数 |
|---|---:|---:|---:|
| video1835 | 304 | 213 | 18 |
| video3796 | 360 | 196 | 8 |
| video6450 | 195 | 160 | 13 |
| video7983 | 204 | 142 | 19 |
| video5346 | 206 | 138 | 11 |

例如video6450在入选时有82.05%被提到第一。每个视频只有20条标注查询。这显示该分数在当前候选分布上会强烈偏爱一些视频；尚未剥离原候选入选机制、主题重复等影响，不能直接断言存在严格的query-independent加性偏置。

二选一置信度并没有在MSRVTT硬负例排序上得到专门验证。共同主题、画面内容与证据显著性可能影响支持度，而“看起来支持描述”并不等价于“在10个高度相近的视频中选中标注实例”。本地上游README列出的能力证据主要是图像问答、rubric与游戏帧；不能据此预期强视频检索重排能力，也不能从这些说明推断训练数据绝无MSRVTT或视频内容。

### 3.3 温度及简单接线不是修复方向

固定两选项下 `P(match)=sigmoid((z_match−z_not_supported)/T)`，T为所有候选共享的正数。改全局温度不会改变候选排序，无法修复本次R@1损失。当前没有发现需要改生产接入代码的缺陷；不应为了把负结果变正而调温度、反转概率或改融合权重。

按简单词数分组，≤7词查询R@1从44.76%到11.98%；≥18词从66.96%到25.18%。粗略含before/after/then等词的548条从66.06%到19.89%，其他9,452条从52.44%到15.83%。这些是透明词法分组、不是人工事件标签或因果分析；下降并不只发生在长句或显式时序词上。

## 4. 能确认与不能确认

- 已确认：原生接口会复现已检查的失败偏好；接入的输入、选项、概率方向、混合候选映射、缓存及排序检查没有解释37.14pp下降的错误证据。
- 已确认：当前固定配置的硬负例区分力远弱于UATVR，直接替换其Top-10顺序会大量破坏已有正确结果。
- 支持但未完全因果分解：细粒度/时序理解弱、四帧证据与完整视频标签不一致、近义候选的单GT标注，以及候选支持度跨视频比较的偏好共同造成任务不匹配。
- 未确认：Laya一般视觉能力不行、换任何模板/证据都无效、四帧独自造成全部下降，或整个上游库/未抽查样本绝无bug。需要另外固定的诊断对照才能分开这些机制；本次未新增科学GPU评估、未改原结果。
